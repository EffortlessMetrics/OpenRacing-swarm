# RIPR static mutation-exposure

RIPR is OpenRacing's static mutation-exposure signal. It catches mutation-shaped
weak-test and weak-oracle exposure earlier and cheaper than runtime mutation
because it analyzes changed code statically at PR time.

## What RIPR answers

RIPR asks whether a changed behavior surface appears exposed to tests and
reviewable or whether the diff creates an oracle gap that could let a mutation
survive unnoticed.

It is useful for:

- production Rust behavior changes;
- parser, protocol, verifier, receipt, and CLI guard-rail changes;
- identifying the first useful test or assertion to add;
- generating review packets that make weak-oracle risk explicit.

## What RIPR does not answer

RIPR does not:

- execute mutants;
- report killed or survived runtime mutation outcomes;
- prove correctness;
- prove release readiness;
- replace cargo-mutants, Miri, fuzzing, coverage, or hardware receipts.

Runtime mutation remains the slower backstop when static exposure suggests the
risk is worth paying for.

## PR usage

For production Rust diffs, run the repo wrapper when available:

```bash
cargo xtask ripr-pr
cargo xtask ripr-pr --check
```

The PR summary should distinguish changed-diff RIPR findings from repo-wide
closure signals. PR-scoped RIPR artifacts are not repo-scope coverage or
release-readiness proof.

## Artifacts

Expected artifacts live under `target/ripr/` or the repo-specific RIPR receipt
location and may include:

- PR summary Markdown;
- repo or diff exposure JSON;
- review packet JSON;
- first-useful-action Markdown/JSON;
- review comments generated by the repo wrapper.

When artifacts are skipped, stale, or advisory-only, the claim boundary must say
so explicitly.
